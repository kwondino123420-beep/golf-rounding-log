# 라운딩 로그 (Golf Rounding Log) — MVP

라운딩을 다니면서 겪는 3가지 문제를 해결하기 위한 웹앱입니다.

1. **골프장/코스별 홀 파(par) 인지 어려움** → 코스를 한 번 등록해두면 라운드마다 각 홀의 파를 자동으로 안내합니다.
2. **이번 홀에 몇 타를 쳐야 하는지, 목표 달성을 위해 앞으로 어떻게 쳐야 하는지 모름** → 참가자별 목표(전체 타수 또는 파 대비)를 설정하면, 매 홀 남은 홀 수 대비 권장 타수와 목표 달성 가능 여부를 실시간으로 안내합니다.
3. **스코어카드 누계 기록 불가** → 홀별 스코어를 기록하면 OUT/IN/TOTAL, 파 대비 누계가 자동 계산되고, 완료된 라운드는 기록 탭에서 참가자별 누계 리더보드(평균 타수, 평균 파 대비, 평균 퍼팅, 베스트 스코어)로 확인할 수 있습니다.

추가로 GPS 기반 모바일 캐디 기능과, 참고 앱들(18Birdies·Golfshot 등)의 핵심 기능 중 일부(스킨스 사이드게임, 퍼팅 기록)도 들어 있습니다.

## GPS 모바일 캐디

- **위치 이용 동의** → GPS로 현재 위치를 확인해 저장된 코스 중 가장 가까운 곳(반경 3km 이내)을 자동으로 찾아줍니다. 홈 화면과 "새 라운드" 화면에서 동작하며, 동의는 최초 1회만 받고 이후에는 조용히 재사용합니다(홈 화면에서 "다시 설정"으로 언제든 초기화 가능).
- **그린까지 거리** → 라운드 중 GPS를 켜면 현재 홀의 그린까지 실시간 거리(m)를 보여줍니다.
- **지도 보기** → OpenStreetMap 기반 지도에 내 위치와 그린 위치를 표시합니다(실제 사용자가 접속했을 때 지도 타일을 무료로 불러오며, API 키가 필요 없습니다).

### 그린 좌표는 어디서 오나요 (중요한 한계)

18Birdies·Golfshot 같은 앱들의 정밀한 코스 지도는 드론 측량이나 유료 라이선스 데이터를 수년간 쌓은 결과물이고, 이런 데이터를 무료로 통째로 가져올 방법은 없습니다. 그래서 이 앱은 **크라우드소싱 방식**으로 그린 좌표를 쌓습니다.

- 그린 위치가 없는 홀에서는 "그린 위치 저장" 버튼으로, 그 자리에서 직접 GPS 좌표를 1회 등록합니다.
- 등록된 좌표는 그 라운드뿐 아니라 내 코스 목록의 해당 코스에도 저장되고, 동반자에게 공유된 라운드를 다른 사람이 불러올 때도 함께 전달되어 누적됩니다(코스 정보가 이미 있으면 없는 그린 좌표만 채워 넣습니다).
- 따라서 정확도는 **누군가 그 골프장에서 실제로 앱을 써본 적이 있는지**에 달려 있습니다. 처음 방문하는 골프장은 그린 좌표가 비어 있을 수 있고, 표시되는 거리는 참고용이며 공식 골프장 지도가 아닙니다.

## 실행 방법

빌드 과정이 필요 없는 순수 정적 페이지입니다. `index.html`을 브라우저로 열거나, GitHub Pages로 바로 배포할 수 있습니다.

```
open index.html
```

또는 저장소 Settings → Pages에서 `main` 브랜치를 배포하면 별도 서버 없이 바로 서비스할 수 있습니다.

## 공유 방식 (MVP의 한계)

현재는 별도 백엔드/서버 없이 동작하는 MVP이기 때문에, "링크를 공유한 사람들끼리 실시간으로 누계를 공유"하는 기능은 **완전한 실시간 동기화가 아니라 링크 기반 스냅샷 공유** 방식으로 구현되어 있습니다.

- 라운드 화면에서 "공유 링크 만들기"를 누르면 현재까지의 라운드 데이터(코스, 참가자, 홀별 스코어)가 URL에 압축되어 담깁니다.
- 이 링크를 카카오톡 등으로 전달하면, 받은 사람이 열었을 때 자동으로 "불러오기" 안내가 뜨고, 확인을 누르면 자신의 기기(로컬 저장소)에 사본으로 저장되어 이어서 기록할 수 있습니다.
- 이후 스코어가 갱신되면 다시 공유 링크를 만들어 전달하는 방식으로 그룹 간 누계를 맞춥니다.

모든 데이터는 각자의 브라우저 `localStorage`에 저장되며, 기기를 바꾸면 데이터가 유지되지 않습니다.

## 코스 정보는 어떻게 쌓이나요

전국 골프장의 홀별 파 정보를 한 번에 긁어오는 무료 공개 API는 없고(정부 공공데이터에도 골프장 이름/주소 정도만 있고 홀별 파는 없음), 지금은 서버도 없는 정적 사이트라 외부 API 연동도 어렵습니다. 대신 다음 방식으로 코스 목록이 자동으로 쌓이도록 만들었습니다.

- 누군가 코스를 한 번 정확히 등록하면 내 코스 목록에 저장됩니다.
- 그 코스로 만든 라운드를 동반자에게 공유하면, 동반자가 링크를 열어 불러올 때 그 코스 정보가 동반자의 코스 목록에도 자동으로 함께 저장됩니다(이미 같은 이름·파 구성의 코스가 있으면 중복 저장하지 않습니다).
- 지금은 각자의 로컬 저장소 단위로만 쌓이지만, 아래 백엔드가 생기면 이 저장 로직을 그대로 "전체 사용자 공용 코스 DB"로 승격시킬 수 있습니다. 코스 위치(GPS)와 그린 좌표도 같은 방식으로 함께 전파됩니다.

## 수익화 (광고)

홈/기록 화면에 광고 영역 자리만 미리 마련해뒀습니다("광고 영역 (준비 중)"). 실제 광고 네트워크(구글 애드센스 등) 연동은 사업자 등록·계정 승인이 필요한 부분이라 여기서 대신 진행할 수 없고, 계정이 준비되면 그 자리에 실제 광고 스크립트만 넣으면 됩니다.

## 다음 단계 (정식 서비스/앱으로 발전 시)

MVP가 잘 동작하는 것이 확인되면 아래 순서로 고도화할 수 있습니다.

1. **실시간 백엔드 도입**: Firebase/Supabase 등으로 라운드 데이터를 서버에 저장 → 링크 하나로 여러 명이 실시간으로 같은 스코어카드를 보고 갱신.
2. **계정/로그인**: 기기가 바뀌어도 내 기록 유지, 친구 목록, 반복 참가자 관리.
3. **코스 데이터베이스 공유화**: 로컬 저장소 기반 코스 목록(위치·그린 좌표 포함)을 서버의 전체 사용자 공용 DB로 승격. 필요하면 골프장 예약 플랫폼 제휴나 공공데이터(전국 골프장 등록현황) 자동완성, 또는 유료 골프 GPS 데이터 라이선스 도입도 검토.
4. **네이티브 앱 전환**: PWA(홈 화면 추가, 오프라인 지원)로 먼저 전환 후, React Native 등으로 iOS/Android 앱 출시. 네이티브 전환 시 백그라운드 GPS, 정밀 그린 앞/중앙/뒤 거리 등도 가능해집니다.
5. **통계/분석 강화**: 파3/4/5별 평균, 페어웨이 적중률, 트렌드 그래프, 목표 대비 달성률 등.
6. **광고 네트워크 연동**: 준비된 광고 영역에 실제 광고 스크립트 삽입.

## 파일 구조

- `index.html` — 앱 전체(마크업, 스타일, 로직)가 담긴 단일 파일. 빌드 도구 없이 정적 호스팅만으로 동작.
